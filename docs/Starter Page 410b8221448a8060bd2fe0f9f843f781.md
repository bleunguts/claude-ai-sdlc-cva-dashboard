## The problem

Monitoring CVA (credit valuation adjustment) by counterparty. The deliverable is a small dashboard: one filterable table of CVA charge per counterparty, backed by 20 mock rows (counterparty, CDS spread, tenor, CVA charge, timestamp). CDS spreads and CVA charges are static mock inputs, not computed — this is a monitoring UI, not a pricing engine.

The project is a vehicle to use one AI tool per SDLC stage and record why. It also exercises prior CVA domain experience (a full-stack CVA UI was previously built in React/C#). Target aesthetic: Bloomberg/AG Grid terminal density, not consumer SaaS.

## The approach — one AI tool per SDLC stage

| Stage | Tool | Result |
| --- | --- | --- |
| Design | Stitch | Light and dark mockups; light variant chosen as the build target |
| Build | Replit Agent | One-page React app in 3 prompts; scaffold needed pruning |
| Component testing | Storybook | Empty / Populated / Error stories for `CvaGrid`; screenshots captured |
| E2E testing | Playwright | 1 passing test: filter on "group" yields 4 rows, BNP Paribas absent |
| Review | CodeRabbit | Blocked — never reviewed the planted edge on PR #21; no review results claimed |
| Docs | Notion AI | This one-pager (in progress) |

Each stage records why the tool was chosen and what actually happened, including failures: the dark-theme detour that contradicted the Module 1 decision, Storybook over-installing and needing to be pruned back, and a hand-counted test expectation (3 rows) that was wrong because "Citigroup" contains "group".

## The stack

React + TypeScript, Vite, Tailwind, Storybook, Playwright. Data: `design/mock-data.json`. Runs locally with plain npm; no backend.

## What I'd change next time

- Check each prompt against recorded decisions before running it.
- Prune or constrain tool defaults early — scaffolds and generators over-deliver.
- Verify third-party integrations on a throwaway PR first (the CodeRabbit install failed silently).
- Derive test expectations from the data, and prove tests can fail.
- Open the rendered output; a green build is not evidence.
